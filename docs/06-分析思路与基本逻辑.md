# 06 · 分析思路与基本逻辑

本文件回答一个问题：**这套东西遇到一个广告账户时，脑子里是怎么跑的。**

---

# 第一部分：分析思路

## 一句话立场

**不做泛泛的策略描述 —— 所有结论都必须落到「改什么、改成多少、为什么」。**

这不是文风偏好，是硬约束。每条判断在代码里都必须带 `reason` 字段，
测试里有一条专门断言 `rule.reason.strip()` 非空（`test_every_verdict_has_reason`）。

## 整体流程

```
拉数 → 诊断 → 决策 → 执行 → 复盘
```

| 阶段 | 产物 | 关键点 |
|---|---|---|
| **拉数** | 广告报表 / SQP 报告 | 官方 API 或后台导出；**不抓页面** |
| **诊断** | 结构化问题清单 | 按固定分层往下切，不跳层 |
| **决策** | 动作清单（P0/P1/P2） | 每条含：对象 / 现值 / 目标值 / 依据 |
| **执行** | 变更记录 | **默认只出方案**，写操作逐条确认 |
| **复盘** | 日报 / 周报 / 月度 | 上周动作必须有「预期 vs 实际」对照 |

## 诊断为什么必须分层，且顺序固定

**上层问题会掩盖下层。** 在错误的层级上调优，等于给歪地基做装修。

```
第 0 层  份额漏斗（SQP）     ← 先定位短板在 曝光/点击/加购/购买 的哪一环
第 1 层  店铺 / 账户          TACoS 趋势、广告占比、是否蚕食自然位
第 2 层  广告活动             预算是否烧穿、ACoS vs 目标、曝光份额
第 3 层  广告组 / 关键词       结构是否混杂、匹配方式是否打架
第 4 层  搜索词               收割 / 否定 / 迁移
第 5 层  广告位               Top of Search / Rest of Search / Product Pages
第 6 层  时段                 预算节奏与竞价
第 7 层  大促期指标解读        CTR↓ + CVR↑ 是正常现象，不是效率下降
第 8 层  新增需求分析         新词 vs 历史词
```

### 第 0 层单独说明：它是「准入判断」，不是「诊断步骤」

**第 0 层的唯一作用是回答一个问题：这次到底该不该动广告。**

用 SQP（品牌分析-搜索查询绩效）把品牌四份额按漏斗排开，找相邻两环节**落差最大**的那处：

| 断崖位置 | 病因 | 动作 |
|---|---|---|
| 点击份额 < 曝光份额 | 主图 / 价格 / 评分 / 标题 | **不要加价** —— 加价只是把钱烧在点不动的流量上 |
| 加购份额 < 点击份额 | 详情页 / 卖点 / 图文 | 不要扩量，先修 A+ 与五点 |
| 购买份额 < 加购份额 | 价格 / 运费 / 优惠券 / 库存 | **不要怪广告** —— 这是转化链路末端问题 |
| 曝光份额极低 + 全站搜索量大 | 没抢到曝光 | 才进入第 2 层，加价 + 加预算 |

> **份额落差在哪一环，钱就不该花在广告上，而该花在那一环。**

这一层防的是投放优化里**最贵的错误**：把转化问题当成出价问题，于是不断加价，越加越亏。

**前置条件**：SQP 需要品牌备案。没有备案时跳过本层，但要明确告知 —— 会失去「转化问题 vs 投放问题」的区分能力。

## 每个动作都要能被复盘

动作清单的标准形态：

| 优先级 | 对象 | 动作 | 依据 |
|---|---|---|---|
| P0 | 活动 X 自动型 | 否定精确 12 个词 | 点击 ≥15 且 0 转化，累计浪费 ≥$X |
| P1 | 关键词 A（广泛） | 出价 0.85 → 0.62 | ACoS 58% > 盈亏线 40%，已过学习期 |
| P2 | 广告位 Top of Search | 加价 0% → 25% | TOS 转化率是其余位置 2.3 倍 |

**P0 = 止血，P1 = 提效，P2 = 增长。**

执行前必须记录**改前值** —— 拿不到改前值的批量工具不要用，因为无法回滚。

# 第二部分：基本逻辑

## 锚点：一切出价决策都挂在盈亏平衡 ACoS 上

**没有这个数，任何「出价该涨还是该降」都是拍脑袋。**

### 四个核心公式

```
① 盈亏平衡 ACoS = 单位广告前贡献 ÷ 售价
   单位广告前贡献 = 售价 − 产品成本 − FBA − 头程分摊 − 平台佣金 − 退货损耗

② 目标 ACoS = (单位广告前贡献 − 目标单件净利) ÷ 售价

③ 可接受 CPC = 售价 × 转化率 × 目标 ACoS      ← 出价天花板

④ 动态点击阈值 = 1 ÷ 转化率                    ← 判断「样本够不够」的线
```

**①与官方口径一致**：Amazon 官方指南把 break-even ACOS 定义为
*"your contribution margin expressed as a percentage"*。
我们只是把扣项做得更细（多扣头程与退货损耗）。

**③是整条链里最有用的一条** —— 它把「出价该定多少」变成算术题：

> 售价 $40、CVR 8%、目标 ACoS 25% → 可接受 CPC = **$0.80**
> 当前 CPC $1.10 > $0.80 → **该词结构性亏损，降价或优化转化，加预算救不了**

**④决定了「什么时候可以下判断」** ——

> CVR 8% 的产品，出一单平均需要 12~13 次点击。
> 25 次点击 0 单？**样本不足，继续观察**，不是否定。
> 若用固定阈值（比如"10 次点击 0 单就否"），这个词早就被误杀了。

## 判据表：每类动作靠什么触发

| 判断 | 判据 | 依据 |
|---|---|---|
| **否定 / 降价（无效花费）** | 点击 ≥ `1 ÷ CVR`，且 0 单 | 动态阈值，非固定值 |
| **否定三条件** | 数字达标 **且** 词义确实不匹配 **且** 连续观察期持续 | 只满足第一条是否词误伤的主因 |
| **降价（亏损）** | ACoS > 盈亏平衡线，点击 ≥ 20 | 20 = 最小统计样本 |
| **收割（转独立 Exact）** | **转化速率 ≥ 1~2 单/周** | **不是 ACoS** —— 稳定转化但 ACoS 差的词恰恰最需要独立活动 |
| **加价（放量）** | ACoS ≤ 目标 × 0.7 | 效率优秀 |
| **保持** | 点击 < 动态阈值 | 样本不足 |
| **广告位加价 / 降价** | 该位 ACoS 相对 **盈亏平衡线** 的倍数 | TOS 1.15×/0.7×、ROS 1.0×/0.7×、PP 1.4×（**PP 无加价档**） |

### 两条容易搞错的

**收割不能用 ACoS 当闸门。** 独立活动是你唯一能单独调它出价的前提；
用 ACoS 筛掉，等于把最需要救的词挡在门外。

**广告位不能用 CVR 倍数判定。** 曝光多、点击多都不足以支持加价 ——
必须同时看到该位带来的订单与销售额。

## 分动作门控：不同动作的风险不同，阈值就该不同

| 动作 | 阈值 | 判错代价 |
|---|---|---|
| 保持 | 0.60 | 少赚 |
| 降价 | 0.80 | 可回收 |
| 加价 | 0.85 | 多花钱 |
| 否定 | 0.85 | **丢流量，不可逆** |
| 暂停 | 0.90 | **丢排名，不可逆** |

**逻辑**：低风险动作门槛低（错了只是少赚），高风险动作门槛高（错了直接丢流量）。
这套阈值来自 45 个真实搜索词的影子对照标定（见 `docs/04`）。

## 双层架构：规则层是主路径，Jev 是影子层

```
广告导出
   ↓
[state_builder]  算好全部派生量，裁剪成最小 state
   ↓
[rule_layer]     规则层 → 动作 + 可追溯依据          ← 主路径
   ↓
[jev_shadow]     Jev → 动作 + 置信度 + 紧迫度        ← 影子层
   ↓
[compare]        一致 / 强度分歧 / 方向分歧
   ↓
[bitable_sync]   落到飞书多维表格供人复核
```

### 为什么不让 Jev 直接决策

| | 规则层 | Jev |
|---|---|---|
| 能否回答「为什么」 | ✅「ACoS 120% > 盈亏平衡线 33.7%，点击 40」 | ❌ 只能说「模型给了 0.83」 |

广告优化最需要的**可解释性**，恰好是决策模型给不了的。把黑盒概率放进主路径，
出问题时无法复盘。

### 那影子层的价值在哪

**在它「不同意」的时候。**

> 规则层在边界上是硬的。ACoS 恰好是目标 1.1 倍时，规则会机械地说「微调降价 10%」。
> 两者不一致 = **这个案例确实模糊**，正是最该让人看的地方。

而分歧检测**只用「选中的答案」，不用置信度的绝对值** ——
恰好用在了 Jev 最可靠的那一面（实测 state 放大 41 倍，答案 10/10 不变；
但置信度会漂 ±0.33）。

### 一个重要的判断经验

**分歧率过高，要先怀疑设计，而不是庆祝发现了分歧。**

第一次 live 调用时 Jev 把 12 个词里的 10 个判成「暂停」（分歧率 91.7%），
连 ACoS 26% 的健康词也是。当时信号很明确：

- 动作分布比规则层更**极端、更单一**
- 置信度区间很窄
- 连明显健康的案例也被判极端动作

根因是 `instructions` 里没写判断口径。补上后分歧率降到 33.3%，自动执行从 1 升到 7。

## 纪律：不可逆动作要二次确认

Jev 有三个输出，作用完全不同：

| 字段 | 问法 | 作用 |
|---|---|---|
| `Jev置信度` | Choice/Score 附带 | **门控**（该不该自动执行） |
| `Jev紧迫度` | Score（0–2 连续） | **排优先级** |
| `无效花费概率` | Noul（0–1） | **安全闸门** |

第三条的用法是硬约束：**>0.80 且动作是否定/暂停 → 强制转人工**。

理由：模型认为这笔钱确实白花了，但否定和暂停**不可逆** ——
即便它对动作很有把握，也值得让人看一眼。

# 一页速查

```
【立场】  结论必须落到「改什么、改成多少、为什么」
【流程】  拉数 → 诊断 → 决策 → 执行 → 复盘
【顺序】  份额 → 店铺 → 活动 → 广告组 → 搜索词 → 广告位 → 时段 → 大促期 → 新词
【锚点】  盈亏平衡 ACoS = 广告前单位贡献 ÷ 售价
【天花板】可接受 CPC = 售价 × CVR × 目标 ACoS
【样本线】动态点击阈值 = 1 ÷ CVR（下限 5）
【收割】  看转化速率，不看 ACoS
【广告位】看 ACoS 相对盈亏平衡线的倍数，PP 只有收紧档
【分级】  P0 止血 / P1 提效 / P2 增长
【分层】  规则层可追溯（主） + Jev 分歧检测（影）
【门控】  低风险动作门槛低，高风险动作门槛高
【红线】  目标不明确不给通用建议；不可逆动作强制人工复核
```
