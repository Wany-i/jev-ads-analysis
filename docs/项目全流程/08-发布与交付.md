## 二、版本策略

### 2.1 两个项目的语义化版本口径

| 项目 | MAJOR | MINOR | PATCH | 证据 |
|---|---|---|---|---|
| `jev-ads-analysis` | 流水线结构或规则层判断逻辑发生不兼容变化 | 新增能力（新分析载体、新决策类型）或带标定数据调整阈值 | 文档与示例修正 | `jev-ads-analysis/CHANGELOG.md:127-131` |
| `amazon-ads-optimization` | 诊断框架或核心公式发生不兼容变化，例如层级重排、公式定义变更 | 新增场景、子命令、参考文档，或补充验证导致阈值调整 | 文字修正、示例补充、无行为变化的修复 | `amazon-ads-optimization/CHANGELOG.md:54-58` |

### 2.2 统一判定规则

| 变更类型 | 建议版本位 | 判断问题 | 例子 |
|---|---|---|---|
| 输入契约变化 | MAJOR | 旧调用方是否可能直接失败或得到不同含义的结果 | 重排流水线阶段、改变规则层动作空间 |
| 用户可见能力增加 | MINOR | 旧用法是否仍成立，同时是否新增了可调用入口或新载体 | 新增 `sweep.py`、新增分析载体、新增子命令 |
| 阈值调整 | MINOR | 阈值是否由新标定或新证据支撑，并改变输出分布 | Jev 保持/降价/否定阈值调整；否定阈值改为 `1 ÷ CVR` |
| 纯文档、示例、错别字 | PATCH | 是否不改变任何可执行行为 | README 示例修正、字段说明补充 |
| 安全边界变化 | MAJOR 或 MINOR | 是否新增写操作、联网路径或凭据要求 | 新增广告写接口应至少按 MAJOR 处理；新增只读联网能力按 MINOR 处理 |

**事实**：`amazon-ads-optimization/CHANGELOG.md:3` 明确声明遵循 Keep a Changelog 与语义化版本。`jev-ads-analysis/CHANGELOG.md` 没有同样的 Keep a Changelog 声明，但其末尾同样给出了 MAJOR/MINOR/PATCH 口径。

### 2.3 变更记录写法

- 未发布内容先进入 `[Unreleased]`，发布时再切成 `[版本号] — YYYY-MM-DD`。证据：`amazon-ads-optimization/CHANGELOG.md:5-11`；`jev-ads-analysis/CHANGELOG.md:3-5`。
- 阈值、公式、设计推翻必须写明「修改前 → 修改后 → 依据」。证据：`amazon-ads-optimization/references/verification.md:195-203`、`:328-338`、`:681-733`。
- 实跑发现的缺陷要写清现象、根因和修法，不能只写「优化了逻辑」。证据：`jev-ads-analysis/CHANGELOG.md:71-88`。
- 发布前要保证版本号一致：`amazon-ads-optimization` 检查 `SKILL.md` frontmatter、CHANGELOG、tag；`jev-ads-analysis` 检查 CHANGELOG、dist 文件名、tag。**推断**：素材只证明这些位置各自存在版本号，不能证明历史上一定做过一致性检查。

### 3.2 用 git archive 创建归档

在 `jev-ads-analysis` 仓库根目录执行。**推荐流程**：

```powershell
$Version = "0.3.1"
New-Item -ItemType Directory -Force dist | Out-Null

git archive --format=tar.gz `
  --prefix="jev-ads-analysis-$Version/" `
  -o "dist/jev-ads-analysis-$Version.tar.gz" HEAD

git archive --format=zip `
  --prefix="jev-ads-analysis-$Version/" `
  -o "dist/jev-ads-analysis-$Version.zip" HEAD
```

为什么优先用 `git archive`：

- 它从 Git 索引生成文件清单，天然排除未跟踪的 `output/`、`.env`、`__pycache__/`、编辑器目录等。证据：v0.3.1 归档内包含 `.gitignore`，其中忽略 `output/`、`.env`、`credentials*`、`*.key`、`__pycache__/`。
- `.gitignore` 同时忽略 `dist/`，因此发布前不要指望 `git ls-files` 能自动检查 dist 里的归档内容。证据：`jev-ads-analysis` v0.3.1 归档内的 `.gitignore`；`tools/check_repo.py:42-50` 只检查 `git ls-files`。
- `.gitattributes` 对 `*.md`、`*.py`、`*.csv` 强制 LF。证据：v0.3.1 归档内的 `.gitattributes`。**推断**：这有利于跨 Windows/Linux 复现文本差异，但不能替代 Windows 下的编码与 `.cmd` 冒烟测试。

### 3.3 生成 SHA256SUMS

Windows PowerShell：

```powershell
Get-ChildItem -LiteralPath dist -File |
  Where-Object { $_.Name -ne "SHA256SUMS.txt" } |
  ForEach-Object {
    $hash = (Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash.ToLower()
    "$hash  $($_.Name)"
  } |
  Set-Content -LiteralPath dist\SHA256SUMS.txt -Encoding ascii
```

Linux/macOS：

```bash
cd dist
sha256sum dataset-redhen-45.csv \
  jev-ads-analysis-0.3.1.tar.gz \
  jev-ads-analysis-0.3.1.zip > SHA256SUMS.txt
```

发布时必须校验：

```powershell
Get-Content -LiteralPath dist\SHA256SUMS.txt
Get-FileHash -Algorithm SHA256 dist\jev-ads-analysis-0.3.1.tar.gz
Get-FileHash -Algorithm SHA256 dist\jev-ads-analysis-0.3.1.zip
```

|---|---|---|
| Jev live 调用 `--jev live` | 需要 `OPENROUTER_API_KEY`；外部模型输出和置信度有波动；可能遇到 429、5xx、超时 | `README.md:24`、`SECURITY.md:15`、`CHANGELOG.md:86` |

| Windows GBK 控制台行为 | CI 跑在 Ubuntu，Linux 默认 UTF-8，不能复现 OEM 936 代码页 | `CHANGELOG.md:82-83`、`tests/test_rules.py:20-24`、`tools/check_repo.py:21-27` |

## 七、本地一键验收

### 7.1 jev-ads-analysis

一键命令：

```powershell
cd _source\jev-ads-analysis
python tools\run_checks.py
```

它依次执行：

1. `python -m unittest discover -s tests`
2. `python tools/check_repo.py`
3. `python src/pipeline.py ... --out output/_checks.json`

任何一步返回非 0，脚本最终返回 1 并打印失败步骤。证据：`tools/run_checks.py:20-44`。

只跑 CI 等价的三件事，也可以分开执行：

```powershell
python -m unittest discover -s tests -v
python tools\check_repo.py
python src\pipeline.py --input examples\input-sample.csv `
  --price 39.99 --cost 8 --fba 7.5 --first-leg 3 `
  --commission-rate 15 --return-rate 5 `
  --target-acos 25 --running-days 30 --bid 0.85 `
  --out output\pipeline-output.json
```

端到端人工判定：未配置 `OPENROUTER_API_KEY` 时，7 行输入应全部落在「待标定」；每行的 `规则层依据` 必须有值，`Jev动作` 应为「未接入」。证据：`ci.yml:46-57`、`tests/test_rules.py:281-302`。

### 7.2 amazon-ads-optimization

素材中没有 `run_checks` 或 CI，因此只能按贡献指南手动跑离线命令。**发布前不要跑需要联网的 `keywords` 子命令**，其余三个子命令可作为离线验收：
