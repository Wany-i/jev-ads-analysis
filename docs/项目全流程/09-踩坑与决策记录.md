### 这类问题以后怎么提前发现

1. **真实响应 fixture 先行**：所有外部模型输出先落一份脱敏的真实响应形状，再写解析、透传、行输出三层断言。参考 J-T:157-163。
2. **端到端不变量必须硬断言**：未接入时自动执行必须为 0、人工复核必须为 0、每行必须有规则层依据。参考 J-CI:48-57。
3. **live 标定放在 CI 之外**：20–50 个真实词、人工看分歧；CI 只跑确定性干跑。参考 `docs/04`:66-78。
4. **副作用也要有测试**：剪贴板备份、网关重试目前是代码修复但没有回归网，属于已有的测试缺口。

## 三、B 类：数据契约与口径缺陷

| # | 现象 | 根因 | 修法 | 证据 | 如何防止复发 |
|---|---|---|---|---|---|
| B1 | 真实报表里自动广告的 `Match Type` 是 `-` 或空；一个非法 select 值让 45 条写入全部失败 | 报表原始值不在多维表格 select 选项里，且同步层没有白名单 | 补全映射：`-`、空、`close match` 等归一到「自动」；同步层加 select 白名单，非法选项跳过该字段而不是整批失败 | J-CL:52-55；J-T:81-89 | 回归测试覆盖 `-`、空字符串、`Auto`、`broad`、`Exact`、`phrase`；未知值必须返回 `None`，由白名单决定跳过字段。证据 J-T:81-89 |
| B2 | 单词无转化时 `1 ÷ CVR` 无法计算，原实现阈值退化为 0，等于永不判断 | 只用单词自身 CVR，没有回填品类 CVR，也没有在回填后重算阈值 | 用品类 CVR 兜底（全量订单 ÷ 全量点击），加载完成后刷新每一行的阈值 | J-CL:118-120；J-T:72-79、:91-105；J-CI:60-69 | 测试必须同时覆盖「零单词用品类兜底」和「非零单词保留自身 CVR」；CI 断言 45 词数据集的每行阈值不低于 5。证据 J-T:91-105、J-CI:66-69 |

### 这类问题以后怎么提前发现

- **用真实导出做契约样本**：不要只用自己造的 `Auto`，至少保存 `-`、空值、大小写混合、未知值四类样本。
- **派生量只在一个地方算，回填后必须重算**：品类兜底 CVR 属于载入阶段的总量字段；任何后回填字段都要触发 `refresh()` 或等价重算。
- **把「阈值下限」做成 CI 不变量**：单行测试之外，再对整个数据集断言 `click_threshold >= 5`。
- **同步层必须遵守「字段失败不等于整批失败」**：枚举白名单只跳过非法字段，不能让一条脏值拖垮整批记录。

## 四、C 类：环境与发布卫生缺陷

| # | 现象 | 根因 | 修法 | 证据 | 如何防止复发 |
|---|---|---|---|---|---|
| C1 | 中文写入剪贴板后读回是乱码 | Windows PowerShell 默认按 OEM 代码页，简体中文环境为 GBK/936；stdin/stdout 与 UTF-8 不一致 | 显式设置 `[Console]::InputEncoding/OutputEncoding = UTF8`；Python 工具把 stdout/stderr 重设为 UTF-8 | J-CL:82-83；J-T:20-24；J-CR:21-27 | 这是 Windows 特有问题，CI 跑 Ubuntu 抓不到。发布前必须在真实 Windows 控制台做一次「中文写入 → 读回 → 比对」冒烟；不要只跑 Linux 测试 |
| C2 | `.cmd` 调用长 JSON 失败，几千字符的中文 JSON 被拆坏 | Windows 下 `.cmd` 经 cmd.exe 二次解析引号，参数边界被破坏 | 改用 npm 布局下的原生 `lark-cli.exe` | J-CL:87-88 | 素材没有自动化测试。建议固定一条 Windows 集成冒烟：构造含中文、引号、换行的长 JSON，调用原生 exe；同时禁止在发布脚本里调用 `.cmd` 包装器 |
| C3 | 命令事故产生一个 0 字节的「盈亏平衡线」文件，混进发布包，打包时才发现 | shell 重定向把中文当成目标文件名；提交前没有卫生检查 | `check_repo.py` 检查 0 字节文件，并检查根目录「无扩展名 + 纯非 ASCII」的可疑文件名 | J-CR:1-10、:53-82；J-CI:32-33 | CI 每次跑 `check_repo.py`。**注意**：它默认走 `git ls-files`，而 `dist/` 被忽略；发布流程还要解压归档或列举归档，检查归档内部没有 0 字节文件。证据 J-CR:42-50 |

### 这类问题以后怎么提前发现

1. **编码边界显式化**：控制台输入输出、文件读写、子进程参数三种边界的编码要分别写死，不能依赖系统默认。
2. **Windows 专项冒烟独立于 Linux CI**：至少覆盖中文往返、长 JSON、引号、换行与 `.cmd` 替代路径。
3. **发布前检查两层文件系统**：第一层是 `git ls-files` 的仓库卫生；第二层是最终 tar.gz/zip 的解压清单与 0 字节扫描。
4. **可疑文件名规则要保留**：纯中文无扩展名根文件是命令事故的强信号，不要因为「看起来能用」就删掉检查。
