# 02 · 分析载体：飞书多维表格

## 为什么用多维表格

分析结果里有三类东西需要**并排看**：

1. **规则层结论 + 依据**（可追溯）
2. **Jev 的动作 + 置信度 + 紧迫度**（第二意见）
3. **处置**（自动执行 / 人工复核 / 待标定）

散在 JSON 里没法用。多维表格的优势正好对上：

| 需求 | 多维表格的能力 |
|---|---|
| 把「分歧案例」挑出来 | 一层 `是否分歧 = true` 的筛选视图 |
| 按优先级处理 | 按 `规则层优先级`（P0/P1/P2）分组 |
| 并排对比两层判断 | 字段天然并排，无需拼接 |
| 留痕 | 记录级历史 + 评论 |

## 表结构

### 主表：关键词判断

| 字段 | 类型 | 来源 |
|---|---|---|
| 关键词 | text（主字段） | 输入 |
| 站点 / 匹配方式 | select | 输入 |
| 曝光 / 点击 / 花费 / 销售额 / 订单 / 运行天数 / 当前出价 | number | 输入 |
| 目标ACOS / 实测ACOS / 盈亏平衡ACOS / 可接受CPC / 动态点击阈值 | number | **代码计算** |
| 规则层动作 | select（加价/降价/暂停/保持/否定） | 规则层 |
| 规则层依据 | text | 规则层（**可追溯**） |
| Jev动作 / Jev置信度 / Jev紧迫度 / 无效花费概率 | select / number | Jev 影子层 |
| 是否分歧 | checkbox | 比对 |
| 处置 | select（自动执行/人工复核/待标定） | 比对 |

### 建议视图

| 视图 | 筛选 | 用途 |
|---|---|---|
| **待复核** | `处置 = 人工复核` | 主要工作面 |
| **分歧案例** | `是否分歧 = true` | 分析两层为什么不同 |
| **P0 止血** | `规则层优先级 = P0` | 优先处理 |
| **待标定** | `处置 = 待标定` | 标定 Jev 前的工作清单 |

## 同步

```bash
# 干跑（只数记录，不写入）
python src/bitable_sync.py --base-token <token> --table-id <table_id> \
  --input output/pipeline-output.json --dry-run

# 实际写入
python src/bitable_sync.py --base-token <token> --table-id <table_id> \
  --input output/pipeline-output.json --as user
```

依赖 `lark-cli` 已登录且具备 `base:record:create` 等写权限。

## 注意

- **不要把真实店铺数据提交到仓库**。同步是运行时行为，不产生仓库文件。
- 比例类字段（`目标ACOS` / `实测ACOS` / `盈亏平衡ACOS`）按小数写入，可加公式列显示为百分比。
- `是否分歧` 用 checkbox，方便做筛选视图。
