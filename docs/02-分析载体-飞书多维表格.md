# 02 · 分析载体：飞书多维表格

## 为什么用多维表格

分析结果里有三类东西需要**并排看**：

1. **规则层结论 + 依据**（可追溯）
2. **Jev 的动作 + 置信度 + 紧迫度**（第二意见）
3. **处置**（自动执行 / 人工复核 / 待标定）

散在 JSON 里没法用。多维表格的优势正好对上：

| 需求 | 多维表格的能力 |
|---|---|
| 把「分歧案例」挑出来 | 一层 `是否分歧 = true` 的筛选视图 |
| 按优先级处理 | 按 `规则层优先级`（P0/P1/P2）分组 |
| 并排对比两层判断 | 字段天然并排，无需拼接 |
| 留痕 | 记录级历史 + 评论 |

## 表结构

### 主表：关键词判断

| 字段 | 类型 | 来源 |
|---|---|---|
| 关键词 | text（主字段） | 输入 |
| 站点 / 匹配方式 | select | 输入 |
| 曝光 / 点击 / 花费 / 销售额 / 订单 / 运行天数 / 当前出价 | number | 输入 |
| 目标ACOS / 实测ACOS / 盈亏平衡ACOS / 可接受CPC / 动态点击阈值 | number | **代码计算** |
| 规则层动作 | select（加价/降价/暂停/保持/否定） | 规则层 |
| 规则层依据 | text | 规则层（**可追溯**） |
| Jev动作 / Jev置信度 / Jev紧迫度 / 无效花费概率 | select / number | Jev 影子层 |
| 是否分歧 | checkbox | 比对 |
| 处置 | select（自动执行/人工复核/待标定） | 比对 |

### 建议视图

| 视图 | 筛选 | 用途 |
|---|---|---|
| **待复核** | `处置 = 人工复核` | 主要工作面 |
| **分歧案例** | `是否分歧 = true` | 分析两层为什么不同 |
| **P0 止血** | `规则层优先级 = P0` | 优先处理 |
| **待标定** | `处置 = 待标定` | 标定 Jev 前的工作清单 |

## 同步

```bash
# 干跑（只数记录，不写入）
python src/bitable_sync.py --base-token <token> --table-id <table_id> \
  --input output/pipeline-output.json --dry-run

# 实际写入
python src/bitable_sync.py --base-token <token> --table-id <table_id> \
  --input output/pipeline-output.json --as user
```

依赖 `lark-cli` 已登录且具备 `base:record:create` 等写权限。

## 注意

- **不要把真实店铺数据提交到仓库**。同步是运行时行为，不产生仓库文件。
- 比例类字段（`目标ACOS` / `实测ACOS` / `盈亏平衡ACOS`）按小数写入，可加公式列显示为百分比。
- `是否分歧` 用 checkbox，方便做筛选视图。

### 实测数据样例

| 关键词 | 点击 | 规则层动作 | 优先级 | 动态点击阈值 | 依据 |
|---|---|---|---|---|---|
| portable blender | 18 | 保持 | P2 | 33 | 点击 18 < 阈值 33，样本不足 |
| blender bottle | 40 | 降价 | **P0** | 40 | ACoS 120.0% > 盈亏平衡线 33.7% |
| smoothie maker | 32 | 降价 | P1 | 11 | ACoS 32.0% 介于目标与盈亏线之间 |
| cheap blender for sale | 25 | 保持 | P2 | 33 | 点击 25 < 阈值 33，样本不足 |
| juicer machine | 60 | 降价 | **P0** | 30 | ACoS 90.0% > 盈亏平衡线 33.7% |

> 注意 `cheap blender for sale`（25 次点击 0 单）判为「保持」而不是「否定」——
> 因为按品类兜底 CVR 推得的阈值是 33 次。**这正是 `1÷CVR` 动态阈值相对固定阈值（如 10 次）的价值。**

## 实践中的坑（均已修复）

| 坑 | 现象 | 修法 |
|---|---|---|
| **载荷形状** | 写入失败 | 必须是 `{"create_records":[...]}`，不是裸数组 |
| **select 的 CellValue** | 写入失败或类型错 | select 必须传数组：`["US"]` 而非 `"US"` |
| **枚举值拼写** | 建表失败 | 颜色是 `Gray` 不是 `Grey` |
| **权限名** | 授权失败 | 是 `base:view:write_only`，不存在 `base:view:create` |
| **Windows 下 .cmd + 长 JSON** | `cannot find the file specified` | `.cmd` 会经 cmd.exe 二次解析引号，**必须改用原生 `.exe`** |

最后一条最隐蔽：短参数时 `.cmd` 能用，一旦 `--json` 载荷有几千字符的中文 JSON，cmd.exe 的引号规则就会破坏命令行。定位方式见 `src/bitable_sync.py` 的 `_resolve_cli()`。
