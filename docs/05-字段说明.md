# 05 · 字段说明（三个 Jev 输出的语义）

飞书多维表格里的这三个字段最容易混淆，**已在表内写入字段注释**（鼠标悬停字段名可见）。
本文件是仓库侧的同一份说明，便于代码与文档对齐。

| 字段 | 问法 | 取值范围 | 回答什么 | 用途 |
|---|---|---|---|---|
| `Jev置信度` | Choice / Score 的附带字段 | 0–1 | 对这个判断有多确定 | **门控**（该不该自动执行） |
| `Jev紧迫度` | Score | 0–2 连续 | 该多快处理 | **排优先级** |
| `无效花费概率` | Noul | 0–1 | 已花的钱是不是白花了 | **安全闸门**（不可逆动作二次确认） |

---

## 一、`Jev置信度`（confidence）

**对「选中的那个动作」有多确定。** Choice 与 Score 都会返回它。

### 易混淆点：confidence ≠ 概率

```json
"动作": {
  "choice": "pause",
  "probabilities": { "pause": 0.69, "lower": 0.25, "negate": 0.03, "keep": 0.01 },
  "confidence": 0.64
}
```

| | `probabilities` | `confidence` |
|---|---|---|
| 含义 | **选项之间**的相对可能性 | 模型对**整个判断**的把握 |
| 用途 | 知道备选是什么（第二名） | **决定该不该自动执行** |

**为什么要分开**：概率可能分得很开（69% vs 25%），但模型仍可能不确定自己的判断依据是否充分。
**门控用的是 confidence。**

官方原话：*"A confidence threshold is not one number. Different actions within the same system
should be gated at different levels depending on the consequences of getting it wrong."*
—— 同一系统里不同动作要用不同阈值，因为判错代价不同。

### 我们的分动作阈值（经 45 词标定）

| 动作 | 阈值 | 理由 |
|---|---|---|
| 保持 | 0.60 | 低风险，错了只是少赚 |
| 降价 | 0.80 | 一致率拐点 |
| 加价 | 0.85 | 样本不足，暂保守 |
| 否定 | 0.85 | 不可逆 |
| 暂停 | 0.90 | 最高风险 |

### 实测分布

| 组 | 均值 | 中位 | n |
|---|---|---|---|
| 与规则层一致 | **0.820** | 0.990 | 35 |
| 与规则层分歧 | **0.555** | 0.460 | 10 |

## 二、`Jev紧迫度`（urgency）

**Jev 认为这个判断该多快处理。** Score 类型 —— 在有序标尺上打分。

```json
"紧迫度": {
  "type": "score",
  "instructions": "处理这个判断的紧迫程度",
  "criteria": ["放着不管", "本周内处理", "今天就该处理"]
}
```

返回：

```json
{
  "score": 1.89,
  "legend": { "0": "放着不管", "1": "本周内处理", "2": "今天就该处理" },
  "probabilities": { "0": 0.02, "1": 0.07, "2": 0.91 },
  "confidence": 0.84
}
```

**`score` 是连续值，不是整数档位。** `1.89` 读作「更靠近『今天就该处理』」。

⚠️ 官方提醒：**不要用 score 插值还原具体数值**
（"score levels are weak in numerical calibration"）—— 它只适合**排序与分档**。

### 实测：它其实在帮我们排优先级

| 组 | 紧迫度 |
|---|---|
| 4 条分歧案例（ACoS 为盈亏平衡线 2–3.6 倍） | **1.82 – 1.90** |
| 一致且健康的词 | 0.67 – 1.67 |

**那 4 个烧钱最狠的词，Jev 的紧迫度全部给到最高档。**

---

## 三、`无效花费概率`（noul）

**Jev 判断「该词到目前的花费确实属于无效支出」的概率。**

Noul 是第三种问法 —— **问一个是/否问题，只返回「是」的概率，没有 confidence**：

```json
"无效花费": {
  "type": "noul",
  "instructions": "该词到目前的花费已经属于明显的无效支出"
}
```

### 用途：安全闸门，不是决策依据

```json
"guards": [{
  "signal": "无效花费", "op": ">", "value": 0.80, "then": "review",
  "why": "模型认为花费明显无效时，即使对动作很有把握也先给人工看一眼
          —— 否定与暂停都不可轻易回滚"
}]
```

**逻辑**：即便 Jev 对「否定这个词」很有把握，只要它同时认为「这笔钱确实白花了」，
也强制转人工 —— 因为否定和暂停**不可逆**。

### 实测：与订单数单调递减

| 订单 | 词数 | 均值 |
|---|---|---|
| 0 单 | 30 | **0.85** |
| 1 单 | 1 | 0.72 |
| 2 单 | 3 | 0.47 |
| 3 单 | 2 | 0.23 |
| 4+ 单 | 9 | **0.17** |

出单越多越不像浪费 —— 说明模型确实在对上「浪费」这个概念，不是随机给数。

### 易误解点

**「动作 = 保持」与「花费可能无效」可以同时成立。**

`保持` 那一组的无效花费概率范围是 **0.15–0.88**。意思是 Jev 可以同时说：

> 动作 = **保持**（样本还不够，别急着动）
> 无效花费 = **0.88**（但已经花掉的这些钱，看着确实白花了）

**"样本不足以下结论" 和 "已花的钱看着浪费" 并不矛盾。**

而且因为「保持」是低风险动作，硬约束不会拦它 —— 这是设计如此（保持错了只是少赚）。

### ⚠️ 不要拿它和 Choice 的概率互相换算

上游调研明确警告：

> **不要指望 `noul` 与 `choice` 的数能互相换算**（同题两者可差 20 倍以上）。
> 官方例：同一判断，`noul` 给 0.22、`choice` 给 0.01；两个 `noul` 相加还能等于 1.19。

**它是独立信号，不是对动作概率的补充说明。**

## 四、在代码里的位置

| 字段 | 解析位置 | 门控逻辑 |
|---|---|---|
| `Jev置信度` | `src/jev_shadow.py` → `judge()` | `_gate()` 按 `GATE_THRESHOLDS` 判定 |
| `Jev紧迫度` | 同上（`score` 字段，兼容 `level`/`value`/`rating`） | 不参与门控 |
| `无效花费概率` | 同上（**`noul` 字段**，不是 `probability`） | `WASFUL_REVIEW_GUARD = 0.80` |

> 这两个字段名都踩过坑：`noul` 读成了 `probability`、`score` 没做兼容，两次都导致值恒为 None。
> 详见 `CHANGELOG.md`。
