# 03 · 与上游仓库的关系

本仓库是**第三个项目**，依赖前两个，不重复它们的内容。

```
Wany-i/amazon-ads-optimization      规则层：阈值与依据（可追溯）
        ↓ 提供 judge 规则
Wany-i/jev-decision-layer           决策层：Jev 调用、门控、边界调研
        ↓ 提供 decide + 边界结论
Wany-i/jev-ads-analysis             本仓库：把两者接起来，做分歧检测
```

## 从 `amazon-ads-optimization` 取用的

| 内容 | 位置 |
|---|---|
| 盈亏平衡 ACoS 口径（含头程与退货损耗） | `references/metrics.md` |
| 动态点击阈值 `1 ÷ CVR`（下限 5） | `references/diagnosis.md` 第 4 层 |
| 收割判据用**转化速率**而非 ACoS | `references/verification.md` V17 |
| 品类 CVR 兜底（单词无转化时） | `references/verification.md` V2 |
| 高风险动作需要更高门控阈值 | `references/actions.md` |

**没有复制的**：那些与决策模型无关的内容（SQP 份额漏斗、大促复盘、渠道地图等）留在原仓库。

## 从 `jev-decision-layer` 取用的

| 内容 | 位置 |
|---|---|
| `ad_keyword_action` 的动作空间与分动作阈值 | `registry/ad_keyword_action.json` |
| 三条硬约束（算术外置 / state 裁剪 / 阈值须标定） | `docs/Jev广告关键词决策-状态设计与实测.md` |
| 官方 9 类失败模式 | 同上第 2 节 |
| 分动作门控阈值与 guards | `registry/ad_keyword_action.json` |
| Jev 的能力边界与官方场景地图 | `docs/Jev决策场景清单.md` |

**本项目没有把 `jev-decision-layer` 的代码 vendor 进来** —— 那边是完整的决策层实现（含 MCP server、
注册表、离线测试），本仓库只需要它的**结论与接口约定**，按需重写更小的实现。

> 若要生产化，建议直接用 `jev-decision-layer` 的 `decide()` 或 MCP server，而不是本仓库的 `jev_shadow.py`。
